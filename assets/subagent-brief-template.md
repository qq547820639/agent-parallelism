# 子 agent 派发 prompt 模板

派发前先确认：这份 brief 的**写作成本低于直接内联做掉的成本**。若不是，别派。

子 agent **完全看不到主会话历史**——它只有你在下面填写的内容。缺什么它就猜什么。

---

## 派发 brief（每个子 agent 一份）

```
你是 <角色>。这是一个独立任务，你没有参与之前的讨论，以下信息是你拥有的全部上下文。

## 目标（可判定）
<一句话。必须是可验证的完成状态，不是"调查一下">

## 背景（最小必要集）
项目：<名称 + 一句话定位>
相关约定：<架构约束 / 字段白名单 / 命名规范——只列与本任务相关的>
契约文件：<contract.md 的绝对路径，让它自己读，不要粘贴>

## 范围（硬边界）
允许触碰：<目录 / 文件 / 概念>
禁止触碰：<显式列出，不能只说"其他文件">
明确不做：<列出>

## 完成判定（命令级，必须可机器执行）
<例如：pytest tests/test_auth.py -x 通过 / tsc --noEmit 无错 / grep 命中数为 0>
自证要求：命令未通过不得回报完成。

## 返回格式（严格 JSON，便于主 agent 直接拼装）
{
  "finding": "<结论，一句话>",
  "evidence": ["<file:line>", "..."],
  "confidence": "high | mid | low",
  "blast_radius": "<影响范围>",
  "verification_passed": true,
  "verification_command": "<实际执行的命令>",
  "blockers": ["<若未完成，说明卡在哪>"]
}

## 纪律
- 不要扩大范围；遇到范围外的问题，写入 blockers 交回主线程。
- 不要回报"看起来没问题"——必须附可复现的命令输出。
- 常量、命名、接口签名一律以契约文件为准，不要自行发挥。
```

## 三个常见写法错误

| 错误写法 | 问题 | 正确写法 |
|---|---|---|
| "调查这个 bug 并修复你发现的问题" | 目标不可判定、范围无界 | "定位 `tests/test_auth.py:42` 失败的根因，在 `src/auth.py` 提出修改，**不改其它文件**，返回结构化摘要" |
| "参考我们之前讨论的架构" | 子 agent 看不到之前 | 把约定逐条写进 brief，或给契约文件绝对路径 |
| 粘贴 500 行背景 | 冗余率 > 0.50 与成功率负相关 | 只给最小必要集 + 文件指针，目标冗余率 **0.41** |

## 分片原则

- 按**概念 / 功能**切（"查清所有 auth 相关代码"），**不按目录**切（目录分片会在跨目录引用处失效）
- 每个分片能独立验证
- 分片之间不共享可变状态；共享则改用 git worktree 物理隔离
